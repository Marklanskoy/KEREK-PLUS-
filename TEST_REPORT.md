## Новые проверки

- Повреждённая вложенная история в JSON, отрицательные/NaN/строковые деньги, повторные ID, неверные даты и неподдерживаемая схема отвергаются до изменения базы. Выбор файла показывает сводку без применения.
- Старые корректные неизвестные товары/избранное не теряются в копии. Повреждённая база3.3 и повреждённая миграция3.0 открывают восстановление, сохраняя исходную строку. Imported pendingOrder очищается, не воспроизводится.
- Первое открытие базы сохраняет точный before-3.4; повторный запуск не заменяет исходный снимок. Явное удаление очищает его, не трогая Finance OS.
- Повреждённые цены/условия/бюджеты не разрешают заказ. Нет NaN-итога, негативной стоимости или выдуманной скидки. JS тестирует границу суток Алматы.
- Детерминированный перебор проверяет арифметику всей корзины, уменьшение полного итога каждой предлагаемой заменой и бюджет готовой подборки. Входные структуры не изменяются.
- Сбой записи откатывает и видимое количество. Искусственная отправка pantry-формы вопреки native HTML-валидации не записывает отрицательное количество.
- Просроченный таймер поиска не меняет экран после перехода в корзину.
- Явно подставленный сервер: задержанный POST, смена темы и повторный submit дают только один запрос заказа. Ошибка каталога после ответа не превращает принятый заказ в «не отправлен». Отдельно подтверждён обычный успешный сценарий. Старый фоновый ответ профиля не откатывает новый локальный товар.
- Справка имеет три рабочих входа и семь FAQ, не изменяет данные. Диагностический download содержит только технические флаги/версию, без адресов, телефона, корзины, расходов и комментариев.
- На320/390/768/1440px проверены корзина/справка в светлой и тёмной теме без горизонтального переполнения. Сохранены тесты мобильной панели над навигацией, истории, черновиков и клавиатуры. RU/KK-подписи и prefers-reduced-motion проверены технически.
- Старые именованные HTML-файлы в выпуске — переходы без исполняемого приложения.

## Модель обновления

В Node используется настоящая WebCrypto SHA-256, подставленные fetch/Response/Cache/Worker events. Проверены установка полной совпадающей пачки; отклонение несовпадающего ресурса до записи пачки; version/build handshake; игнорирование API/чужих путей; использование кэша текущего build при ошибке сети/хеша; изоляция чужих кешей. Это не регистрация настоящего Service Worker в браузере.

CSP готового HTML сверяется по SHA256 inline-скрипта. В in-process сервере проверены CSP-заголовки HTML, серверный режим, иконки, манифест и отсутствие кэширования API.

## Что именно подменяется

UI загружается через `set_content`, только тестовый экземпляр лишён CSP для вставки стенда. localStorage/sessionStorage и Web Locks — явные модели Map. Фотографии и внешняя сеть блокируются: значки-заглушки НЕ являются доказательством сломанных фотографий на сайте. Серверные ответы в новых DOM-тестах явно подставлены и не отправляют реальные заявки.

Проверка in-process API использует временную SQLite; она не равна Docker/HTTPS-развёртыванию. Работа сохранения на Map не доказывает сохранение при закрытии настоящего Safari. Same-document History в Chromium не является проверкой жеста «назад» на физическом iPhone.

## Не проверено / не подключено

Native localStorage/Web Locks, реальная установка Service Worker и холодный offline-запуск, Safari/iPhone/Android/VoiceOver, реальная мобильная клавиатура, Docker-сборка, нагрузка и полный аудит безопасности. Не подключены настоящая доставка/поставщик/склад, оплата, SMS и внешняя нейросеть. Нет обещания автоматической доставки локального отзыва владельцу. Казахская редактура носителем не выполнялась.

Строгий валидатор не ремонтирует неправильно отредактированные личные копии. Контрольная сумма файла не заменяет доверенную подпись. Данные и JSON не зашифрованы; локальный снимок не спасает при удалении всего браузерного хранилища.

## Приёмка на устройстве перед важными записями

Сохранить внешний JSON. Загрузить полный Update.zip на прежний адрес. Закрыть старые вкладки, открыть update.html. Сверить несколько реальных записей. В тестовом наборе: добавить/изменить товар и расход, закрыть и снова открыть; проверить сохранение; экспортировать; в отдельном тестовом профиле проверить импорт; проверить второй read-only таб и передачу редактирования; после успешного онлайн-запуска проверить offline, не очищая личную базу. Не вводить настоящие платёжные сведения в демо.

Повторяемый запуск исходников: `python tools/check_release.py --ui`. Это контроль регрессий, не обещание «совершенства навсегда».
