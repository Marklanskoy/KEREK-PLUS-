# KEREK 3.2 — Надёжная корзина · Autopilot 2.0

Дата подготовки: 13 октября 2026 года. Обновление существующего KEREK 3.0/Autopilot 1.1, а не новый магазин с нуля. Основа: `Marklanskoy/KEREK-PLUS-`, commit `c0e8f2dbfd4fa3ddebf1d13ea49553c0024c04a6`.

**Выпуск подготовлен локально. На GitHub и хостинг автоматически не загружен. Каталог, цены, остатки и заказы остаются демонстрационными. Оплаты, SMS, реальной доставки и внешней нейросети нет.**

## Установка с iPhone — без редактирования кода

1. Пока прежняя версия открывается, сохраните «Профиль → Настройки → Экспорт JSON». Старый экспорт не включал отдельные расходы Autopilot: не очищайте старые записи, дополнительные данные сохранятся кнопкой на странице обновления.
2. Распакуйте `KEREK_3_2_Update.zip`. Загрузите **содержимое** в корень прежнего репозитория `Marklanskoy/KEREK-PLUS-` через **Add file → Upload files**. Замените совпадающие имена. Не загружайте сам ZIP и не создавайте внешнюю папку. `index.html`, `sw.js`, `update.html`, `release.json`, иконки должны лежать рядом.
3. Сохраните **Commit changes**. Оставьте прежний адрес, домен, папку и настройки публикации. Дождитесь успешного GitHub Pages build/deploy.
4. Закройте остальные вкладки KEREK и установленную на домашний экран копию. В **том же браузере и по прежнему адресу** откройте после публикации:
   `https://marklanskoy.github.io/KEREK-PLUS-/update.html`
5. Нажмите **«Сохранить копию перед обновлением»**. Сохраните JSON в «Файлы»/внешнее защищённое место, затем отметьте «Я сохранил копию» и нажмите **«Открыть KEREK 3.2.0»**.
6. Страница проверит согласованность HTML и release.json и установит файлы. Старая база переносится при первом запуске один раз; оригиналы остаются локально до явного выхода/удаления данных.
7. Сверьте корзину, избранное, адреса, историю заказов. На главной нажмите **«Открыть список»**, затем **«Мои расходы»** — старые вручную внесённые расходы должны быть здесь. Скачайте новый полный экспорт.

**Не очищайте Safari/Chrome, localStorage, IndexedDB. Не удаляйте прежний репозиторий. Не загружайте личные JSON на публичный GitHub.** Другой браузер/приватная вкладка/другой домен не видят прежнее локальное хранилище. Ссылка выше является маршрутом после загрузки файлов, а не подтверждением публикации этого выпуска.

Если вторая вкладка показывает «Только просмотр», закройте первую и перезагрузите оставшуюся. При отсутствии Web Locks в браузере запись отключена намеренно: используйте современный поддерживаемый HTTPS-браузер. Это защита от потери данных, а не разрешение очищать хранилище.

## Первые пять минут

### Обычные покупки

Главная → **«Открыть список»** → **«Выбрать товары»**. История и избранное дают подсказки, но ничего не добавляют автоматически. Укажите, например, **4 упаковки молока на неделю для своей семьи**. Не надо вводить число людей: неработающее поле убрано. Количество — ваше подтверждённое решение, а не выдуманный рацион ИИ.

Выберите бюджет **всей покупки с доставкой**. Нажмите **«Посмотреть подборку»**: это только черновик, корзина не меняется. В нём можно изменить количество, исключить товар, выбрать «Дополнить корзину» или «Заменить корзину». Показан полный итог, включая текущие позиции, доставку, скидки и бонусы.

**«Применить к корзине»** доступно, когда предложение укладывается в установленный лимит, минимальную сумму и остатки каталога. Недостающие или слишком дорогие позиции не выбрасываются молча. В режиме дополнения уже достаточное количество того же товара не добавляется повторно. Повторный просмотр не меняет корзину. Замена требует отдельного подтверждения. Применение не является оплатой или заказом.

### Домашние запасы

Откройте **«Мои запасы»**. Старые строки сохранены, но без даты проверки они не вычитаются из покупок. Откройте запись, проверьте фактическое количество и срок, подтвердите наличие. Одинаковое правило действует в рецептах и Autopilot: положительное количество, совпадающие единицы, подтверждение не старше 14 дней, указанный срок не истёк. 14 дней — выбранное правило актуальности записи, не срок безопасности продукта. Приложение не может проверить состояние еды.

### Личный бюджет

Autopilot → **«Мои расходы»**. Добавляйте **фактически оплаченные покупки**, дату и комментарий. Любую запись можно изменить или удалить. Тестовые заказы показаны отдельно и не уменьшают личный бюджет. Если лимит превышен, видна величина превышения. Выписок банков и автоматической фиксации реальных оплат нет.

### Выгодные замены

В корзине KEREK Save показывает только предложения, уменьшающие **общую сумму заказа**, а не только стоимость отдельного товара. После изменения доставки, промокода, бонусов, зоны или остатков предложение проверяется повторно. Возможные изменения марки и состава остаются важными: сравнение по базовому ингредиенту не означает идентичное качество или состав.

### Экспорт, восстановление и выход

Профиль → Настройки: **«Экспорт JSON»**, **«Импорт JSON»**, **«Копия для восстановления»**. Новый экспорт включает корзину, заказы, настройки и регулярные количества Autopilot, вручную внесённые расходы. Импорт заменяет, а не объединяет истории; требуется подтверждение. Перед импортом текущая база сохраняется в отдельный локальный снимок. Поддерживаются полный экспорт 3.0/3.2 и копия страницы обновления с данными `kerek_v3`/новой схемы. Старый экспорт 3.0 не может восстановить то, чего в нём никогда не было: отдельные расходы берите из копии страницы обновления.

Автоматическая миграция на прежнем адресе поддерживает старые ключи KEREK 2.0 и 3.0. С повреждёнными данными не продолжайте наугад: используйте экран восстановления, сохраните оригинал.

**Выход теперь явно удаляет локальные записи и расходы после подтверждения**, сохраняя язык/тему. Полное удаление удаляет также локальные страховые копии и старые ключи KEREK. Внешние скачанные JSON пользователь удаляет отдельно. Данные других приложений (например, FINANCE OS) не затрагиваются. В серверном режиме выход не удаляет сам удалённый аккаунт; локальные расходы Autopilot НЕ синхронизируются с сервером — экспортируйте их перед выходом.

### Отзывы

В статической версии сообщение — **локальный черновик, не отправлен владельцу**. После сохранения предлагаются «Скопировать» и «Поделиться». Отправьте текст владельцу в согласованном канале. Получателя приложение не угадывает; открытие системного меню не доказывает доставку. В отдельной серверной сборке сохранена отправка авторизованных обращений в админ-панель.

## Структура исходников и запуск

`public/` — редактируемые JS/CSS и иконки. `build.py` собирает целиком HTML с проверяемым CSP-хешем. `tools/` — service worker и страница обновления. `server/` — демосервер FastAPI, SQLite, роли, заказы, серверные расчёты. `tests/` — проверки. `dist/` — файлы для GitHub Pages. `dist-server/` — аналогичные файлы с явно включённым серверным режимом.

**Не запускайте папку `public/` как готовый сайт. Не редактируйте только копию `app.js` в `dist/`: исполняемый код находится внутри собранного `index.html`.** Изменяйте исходник и пересобирайте. Никаких npm/CDN-зависимостей для сборки сайта нет.

```bash
python build.py
python -m http.server 8000 --directory dist
```

Локальный адрес: `http://127.0.0.1:8000`. Для сохранения нужен браузер с Web Locks; на мобильном используйте HTTPS. Предпросмотр HTML через приложение «Файлы» на iPhone не является поддерживаемым запуском.

Серверная бета (Python 3.13):

```bash
python -m venv .venv
# macOS/Linux:
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python build.py
python -m server.manage create-admin --username admin
python -m uvicorn server.app:app --host 127.0.0.1 --port 8000
```

Администратор создаётся в терминале со своим паролем (минимум 14 символов). Страница `/admin`, не GitHub Pages. Не публикуйте SQLite, пароль или JSON. В `.env.example` справочные переменные; файл автоматически не читается. Для закрытого HTTPS-стенда задайте `KEREK_ORIGIN`, `KEREK_ALLOWED_HOSTS`, `KEREK_SECURE_COOKIES=1`, вынесите SQLite из web-каталога. Docker: сначала `python build.py`, затем `docker compose up --build`; создание администратора — `docker compose exec kerek python -m server.manage create-admin`. Docker в текущей проверке не собирался.

**Сервер намеренно поддерживает только демонстрационный режим. Не отключайте эту защиту, считая её готовой интеграцией оплаты.**

## Ограничения

- Это рабочая бета, не запущенный продуктовый магазин. Реальные поставщики, цены, оплата, доставка, SMS и AI отсутствуют.
- Локальная база и JSON НЕ зашифрованы. Данные доступны программам этого origin и человеку с доступом к браузеру. Храните внешние копии безопасно.
- При потере устройства/очистке браузера локальные страховые копии тоже потеряются.
- Запись допускается только в одной вкладке 3.2. Нет объединения конкурентных изменений между разными устройствами. Web Locks без поддержки браузером означает режим просмотра.
- Предыдущая версия 3.0 не понимает новую схему. После перехода не используйте старый HTML/старые вкладки. В новую базу перенос один раз; последующие изменения старой версии не подмешиваются.
- Регулярные количества выбирает пользователь. Нет расчёта полноценного питания семьи или гарантии актуальности реальных запасов.
- Рецепты/аналоги работают по демонстрационным ингредиентам. Не используйте их для решений об аллергии без проверки реальной упаковки.
- В серверной версии личные расходы и регулярный список Autopilot локальны; синхронизация этого расширения не реализована. Не обещается безопасная совместная работа нескольких устройств.
- Поддержка в статической версии — копирование/ручная отправка, не автоматическое получение обращений владельцем.
- Native Web Locks/localStorage, service worker/PWA, установленная иконка и физический iPhone/Android не проверены здесь. Работа в DOM-модели не заменяет этих проверок. Выпуск не проходил полный аудит безопасности и нагрузки.
- Переводы новых экранов на казахский не прошли отдельную редактуру носителем языка.
