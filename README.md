# KEREK 3.0

**Рабочее развитие KEREK 2.0: магазин, планирование покупок и серверная система тестовых заказов.**

Оранжево-жёлтый адаптивный интерфейс, русский и казахский языки, светлая и тёмная темы. Внутри — 32 демонстрационных товара и 12 рецептов, каталог с фильтрами, корзина, планирование по бюджету, домашние запасы, профиль, история заказов, поддержка, бонусный журнал и отдельная админ-панель.

> **Это ещё не коммерческий сервис доставки.** Цены, товары, марки, остатки и заказы тестовые. SMS не отправляются, деньги не списываются, курьер не вызывается. Вход покупателя использует явно показанный тестовый код — это НЕ подтверждение владения номером. Не размещайте открытый демонстрационный сервер с персональными данными настоящих покупателей. Режим `live` намеренно заблокирован.

## 1. Самый простой просмотр

Откройте `KEREK_3_0.html` в обычном браузере на компьютере. Это самостоятельный файл: каталог, подбор, рецепты, запасы, избранное, локальные тестовые заказы и настройки работают без установки сервера.

В предпросмотрщике файлов на телефоне выполнение JavaScript может быть ограничено. Для просмотра на телефоне опубликуйте статическую сборку или откройте доступный тестовый сервер через браузер.

**Локальный режим:** данные хранятся только в localStorage конкретного браузера и адреса сайта. Они не переносятся автоматически на другой телефон. Очистка данных сайта удаляет их. Отключённое/недоступное хранилище обозначается предупреждением. Оригинальные ключи KEREK 2.0 мигрируются, только если новый файл открыт на том же origin, где были старые данные. Для `file://` поведение хранилища зависит от браузера; надёжнее одинаковый адрес `http://localhost` или опубликованного сайта.

Фотографии — внешние иллюстрации, не подтверждённые фотографии SKU. Без доступа к изображениям отображаются значки. Копии сторонних фотографий в архиве не вложены. Подробнее: [ASSETS](docs/ASSETS.md).

## 2. Полная версия с сервером и базой

Из корня распакованного проекта. Проверено на Python 3.13.5; версии библиотек зафиксированы в `requirements.txt`.

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m server.manage create-admin --username admin
python -m uvicorn server.app:app --host 127.0.0.1 --port 8000
```

### Windows PowerShell

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m server.manage create-admin --username admin
python -m uvicorn server.app:app --host 127.0.0.1 --port 8000
```

Если политика PowerShell не разрешает активацию, не нужно менять глобальную политику: вызывайте `.\.venv\Scripts\python.exe` вместо `python` в командах.

Администратор создаётся командой `manage`. Пароль вводится без отображения и должен содержать минимум 14 символов. **Готового административного пароля нет.**

Откройте:

- Магазин: `http://127.0.0.1:8000/`
- Управление магазином: `http://127.0.0.1:8000/admin`
- Документация API: `http://127.0.0.1:8000/api/docs`

Для отдельного сотрудника с ограниченными правами:

```bash
python -m server.manage create-manager --username manager
```

Сотрудник может управлять товарами, заказами и обращениями, но не правилами магазина, категориями и журналом аудита. Пользовательские данные и пароли не вложены в исходную поставку. SQLite создаётся автоматически при первом запуске в `server/data/kerek.sqlite3`.

### Как проверить полный цикл

Откройте профиль покупателя → войдите по тестовому номеру → подтвердите согласие → введите код, явно показанный в интерфейсе. SMS не придёт. Добавьте товары, укажите адрес, время и согласие на тестовый заказ. Создайте заказ.

Откройте `/admin` в **отдельном профиле браузера или другом браузере**: администратор и покупатель используют одну сессионную cookie на origin, поэтому вход администратора в соседней вкладке заменит покупательскую сессию. В панели откройте заказ и последовательно измените его статусы. Обновите заказы покупателя. Бонусы начислятся только после явного завершения тестового заказа.

Если переключили пользователя и интерфейс сообщает, что сеанс изменился, выйдите и войдите снова. Нельзя считать скрытые кнопки защитой: права проверяются API.

| Каталог | 32 SKU, категории/часть подкатегорий, названия RU/KK, поиск по бренду и названию, близкие опечатки, фильтры цены/бренда/акций/наличия, сортировка, цена за кг/л/штуку |
| Персональные разделы | Избранное, просмотренные товары, рекомендации из избранного, часто покупаемые по реальным тестовым заказам — без выдуманной истории |
| Корзина | Количество, удаление/восстановление, сравнение более дешёвых упаковок, промокоды, доступные бонусы, стоимость доставки и окончательный итог |
| Подбор | Параметры бюджета, людей, количества приёмов пищи, времени готовки, вида питания, исключений; разбор ограниченных RU/KK шаблонов; объяснимый подбор из каталога |
| Рецепты | 12 рецептов с шагами, пересчёт порций, общих ингредиентов, целых упаковок, остатков и подтверждённых домашних запасов; замена блюда и продукта |
| Домашние запасы | Количество/единицы/срок, ручная корректировка, подтверждаемый импорт из заказа, напоминания внутри приложения; просроченное и неподтверждённое исключается из расчётов |
| Покупатель | Тестовая сессия, профиль, несколько адресов, настройки, синхронизация корзины/избранного/запасов, экспорт и удаление/обезличивание данных |
| Заказы | Серверная проверка цен, резервирование остатков, защита повторной отправки, история, повтор по текущим данным, отмена с возвратом резерва и списанных тестовых бонусов |
| KEREK Club | Настраиваемые проценты, бонусный журнал, ограничение списания, реферальный код, однократное начисление за первый завершённый заказ приглашённого |
| Поддержка | Обращения/запросы возврата, связь с собственным заказом, ответы сотрудника внутри приложения |
| Админ-панель | Товары, архивирование, загрузка фото JPEG/PNG/WebP, категории, остатки/цены, ручные статусы заказов, ответы, промокоды, тарифные зоны, бонусные правила, сводка и журнал действий |
| Инфраструктура | FastAPI + SQLite, роли, scrypt-пароли, HttpOnly/SameSite cookie, CSRF, лимит попыток входа, валидация, транзакции, API OpenAPI, независимые доменные расчёты |

**Главное ограничение KEREK AI:** это не подключённая языковая модель. Используется детерминированный алгоритм и ограниченный разбор текста. Он не понимает произвольный разговор и не составляет клинические/нутрициологические рационы. «5 дней» означает 5 выбранных завтраков либо ужинов, а не полное питание семьи на все дни. При недостатке бюджета приложение показывает неполный план или ошибку, а не выдумывает товары.

## 4. Публикация

### GitHub Pages — только статическая версия

Вариант A: переименуйте `KEREK_3_0.html` в `index.html`, загрузите в корень выбранной ветки репозитория и включите публикацию Pages из этой ветки.

Вариант B: загрузите **содержимое** `public/` в корень публикуемой ветки: `index.html`, `styles.css`, `js/`, `assets/`, `sw.js`, `manifest.webmanifest`, `admin.html`. При этом админ-панель покажет, что нужен сервер. Она не становится защищённой серверной системой на Pages.

Никакая база SQLite, Python API, серверные сессии и реальные интеграции на GitHub Pages не запускаются. GitHub описывает Pages как хостинг статических файлов: https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages

**Не публикуйте `server/data/`, `.env`, пароли, выгрузки персональных данных или базу!**

### Полный проект — закрытый тестовый стенд

Используйте машину, где можно запустить Python-процесс и сохранить SQLite между перезапусками. Для тестов достаточно одного Uvicorn-процесса. Перед внешним доступом необходимы HTTPS, ограничение доступа к стенду (например, VPN или отдельная внешняя авторизация), разрешённый hostname, корректный origin, резервное копирование базы и изображений. Не доверяйте заголовкам proxy без настройки доверенного прокси.

Пример окружения для **закрытого HTTPS-стенда**, не для приёма реальных заказов:

```bash
export KEREK_MODE=demo
export KEREK_DB=/absolute/private/path/kerek.sqlite3
export KEREK_ALLOWED_HOSTS=staging.example.com
export KEREK_ORIGIN=https://staging.example.com
export KEREK_SECURE_COOKIES=1
python -m uvicorn server.app:app --host 127.0.0.1 --port 8000
```

Настройте reverse proxy на `127.0.0.1:8000`. При локальном HTTP оставьте `KEREK_SECURE_COOKIES=0`, иначе браузер не отправит Secure-cookie. Файл `.env.example` — справочник; сам сервер автоматически `.env` не читает. Экспортируйте переменные оболочкой или настройками хостинга.

Для контейнерного стенда приложены `Dockerfile` и `compose.yaml`. Сборка контейнера и установка зависимостей требуют сети. Docker-запуск в этой среде не выполнялся. По умолчанию порт доступен только на локальном компьютере:

```bash
docker compose up --build -d
docker compose exec kerek python -m server.manage create-admin --username admin
```

## 5. Тесты и пересборка

```bash
python -m pip install -r requirements-dev.txt
python -m playwright install chromium
python -m pytest tests -q
node --test tests/core.test.cjs
python scripts/build.py
```

Для тестов нужен Node.js; само приложение работает без сборки и без Node.js. В среде сборки использован Node 22.16.0. Браузерные тесты используют `/usr/bin/chromium`, когда он установлен, иначе Chromium Playwright.

`scripts/build.py` создаёт самостоятельный HTML и ZIP без базы, паролей, кэшей и тестовых загруженных изображений. Не запускайте эту команду как способ резервного копирования данных магазина: это сборщик исходников.

Результаты и честное описание границ проверки: [TEST_REPORT](docs/TEST_REPORT.md).

## 6. Перед настоящим запуском

Пока не реализованы реальные SMS, получение каталога/остатков поставщика, online payments/Kaspi, финансовые возвраты, геокодирование/полигоны доставки, API курьера, фоновые push и LLM. В `server/providers.py` есть **контракты интерфейсов**, но не вымышленные подключения.

Также необходимы коммерческие правила заказов/замен/возвратов, проверка персональных данных и инфраструктуры применительно к месту работы, независимый аудит безопасности, нагрузочная проверка, резервирование, мониторинг, подтверждённые составы/аллергены/фото и проверка казахского перевода носителем языка. Не нужно включать `live`, убрав одну защитную строку: сначала реализуются и проверяются эти условия.
