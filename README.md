# KEREK PLUS 3.5.0 — премиальная анимация входа

Обновление объединяет исправления KEREK 3.4.0/3.4.1, ставит выбранный глянцевый оранжевый знак KH и добавляет реальную анимацию при запуске приложения. Данные, корзина, избранное и история личных расходов сохраняются.

**Установка:** в старой версии экспортируйте JSON через «Профиль → Настройки». Распакуйте `KEREK_PLUS_3_5_Update.zip` и загрузите **содержимое** в корень прежнего репозитория `Marklanskoy/KEREK-PLUS-`, заменяя совпадающие файлы. После Commit changes и завершения публикации GitHub Pages откройте `https://marklanskoy.github.io/KEREK-PLUS-/update.html` в том же браузере. Сохраните копию кнопкой на странице, затем перейдите в KEREK PLUS 3.5.0. **Не очищайте Safari и не загружайте личные JSON на GitHub.**

**Анимация:** эмблема появляется с мягким увеличением; вокруг движутся золотистые кольца, по значку проходит блик, проявляется текст KEREK PLUS и точки ожидания. После подготовки базы и интерфейса заставка плавно уступает место готовой странице. При быстрой загрузке вступление длится около 0,95 с; если данные загружаются дольше — экран ждёт фактической готовности без выдуманных процентов. При системной настройке «Уменьшение движения» декоративная анимация отключается. При ошибке экран освобождает место восстановлению без очистки данных.

**Ограничения:** веб-бета без реальной оплаты, доставки, SMS и внешней нейросети; GitHub Pages не запускает сервер. На реальном iPhone и установленной PWA ещё нужна проверка.

# KEREK PLUS 3.5.0 — ваша аватарка и анимированный запуск

Подготовлено 13 октября 2026. Основа — KEREK 3.4.0, commit `fc3d2036c8e6b673144d5b5ed3e6807e6955343f` репозитория `Marklanskoy/KEREK-PLUS-`. Это полный комплект обновления прежнего приложения, не новый магазин и не автоматическая публикация.

## Что изменено

Использован именно присланный `IMG_2263.jpeg`: оранжевый знак в белом круге на чёрном фоне. Изображение не перерисовано, не перекрашено, не обрезано и не растянуто. Исходные 105 × 114 пикселей сохранены в `brand-original.jpg`. Для квадратных иконок добавлены 4 пикселя слева и 5 справа в цвет исходного угла, затем выполнено пропорциональное масштабирование. Увеличенные файлы не восстанавливают отсутствующие в маленьком исходнике детали.

Одна аватарка используется в шапке и подвале, гостевом/пользовательском профиле, карте лояльности, окне «О проекте», начальном экране, восстановлении, админ-панели, странице обновления, перенаправляющих старых страницах, favicon и Apple Touch Icon/PWA. Имя пользователя не меняется.

На запуске — неподвижная аватарка, вращающееся кольцо и мягкая смена точек. Экран завершается по реальной готовности приложения. Нет выдуманных процентов, 100% до готовности или принудительного ожидания нескольких секунд. При быстром запуске заставка короткая. На переходах между разделами заново не появляется. Уменьшение движения в системе отключает декоративные анимации. При ошибке данных заставка снимается сразу; при незавершённом запуске после 12 секунд появляется помощь, а не вечное вращение. Никакие записи ради анимации не удаляются.

## Установить на прежний сайт

1. В текущем KEREK: **Профиль → Настройки → Экспорт JSON**. Сохраните свою копию отдельно. Не загружайте личный JSON в публичный репозиторий.
2. Распакуйте `KEREK_PLUS_3_4_1_Update.zip`. Через **Add file → Upload files** загрузите **содержимое** в корень прежнего `Marklanskoy/KEREK-PLUS-`. Замените одноимённые файлы. Нужны все файлы: HTML, скрипты, иконки, manifest, `sw.js`, `release.json`. Сам ZIP и дополнительная внешняя папка не нужны.
3. Нажмите **Commit changes**, дождитесь публикации и закройте остальные вкладки KEREK, в том числе установленную копию.
4. В прежнем браузере и на прежнем домене откройте:
   `https://marklanskoy.github.io/KEREK-PLUS-/update.html`
5. Нажмите **Сохранить копию перед обновлением**, сохраните файл, подтвердите это и нажмите **Открыть KEREK 3.5.0**.
6. Сверьте корзину, избранное, расходы и адреса. Сохраните новую внешнюю копию.

**Не очищайте Safari, localStorage, историю с данными сайта или базу приложения. Не создавайте пустую базу и не меняйте адрес ради новой иконки.** Обновление сохраняет `version:32` и ключ `kerek_3_2:<путь приложения>`. Старые записи уже поддерживаются кодом 3.4.

Иконки получили отдельные новые имена `icon-ref-*-341.png`. Для старых ссылок обычные `icon-*.png` тоже заменены. Это обновляет ресурсы проекта, но не даёт программе контроль над кэшем уже установленного ярлыка iPhone. Обновление иконки на физическом устройстве не проверено. Не удаляйте установленную PWA/данные только ради изображения без внешней копии.

## Что не менялось

Ядро цен/корзины, модель хранения, проверка данных, Autopilot, транспорт API и каталог побайтово совпадают с 3.4.0. Изменения основного `app.js` касаются отображения бренда и сигналов начала/завершения заставки, а не правил покупок. База не переименована. Autopilot остаётся 2.2.0.

Это всё ещё демонстрационный магазин: нет реальной оплаты, доставки, SMS, банковских интеграций и внешней нейросети. Сохранённая Python-серверная часть запускается отдельно; GitHub Pages её не выполняет. Локальные данные и экспорт не зашифрованы.

## Исходники и проверка

`public/brand-original.jpg` — исходник пользователя; `brand.js` — единый встроенный PNG; `brand.css` — оформление и анимация; `boot.js` — жизненный цикл заставки и watchdog. `build.py` генерирует согласованные `dist/` и `dist-server/`, CSP, release.json и контрольные суммы service worker.

```bash
python build.py
node --test tests/core.test.cjs tests/reliability.test.cjs tests/cart.test.cjs tests/hardening.test.cjs tests/package.test.cjs tests/brand.test.cjs
python -m pytest tests/test_api.py tests/test_release.py -q
python tests/ui_model.py
python tests/brand_ui_model.py
# Корзина: полный набор, можно запускать ограниченными частями:
CASE_START=1 CASE_END=10 python tests/cart_ui_model.py
CASE_START=11 CASE_END=20 python tests/cart_ui_model.py
CASE_START=21 CASE_END=30 python tests/cart_ui_model.py
CASE_START=31 CASE_END=38 python tests/cart_ui_model.py
```

Для сервера используйте прежние инструкции в `docs/PREVIOUS_3_4_README.md`. Версия HTTP health обновлена до 3.5.0; бизнес-логика сервера не переписана.

Сводка фактически выполненных проверок — `TEST_REPORT.md`. DOM-модель не является проверкой на физическом телефоне или установленной PWA.
