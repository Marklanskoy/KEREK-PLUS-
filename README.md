# KEREK 3.3.0 — Корзина без сюрпризов

Дата подготовки: 13 октября 2026 года. Обновление существующего KEREK 3.2.0, Autopilot 2.1.0. Основа — репозиторий `Marklanskoy/KEREK-PLUS-`, commit `0d9d9228b29a25efb93f90410c25286ed65cc92a`.

**Это готовые файлы обновления, а не автоматическая публикация. Подключение к GitHub предоставляет только чтение. Реальные магазин, оплата, доставка, SMS и внешняя нейросеть не подключены. Каталог и заказы остаются демонстрационными.**

## Установить с iPhone, сохранив записи

1. В прежнем KEREK откройте **Профиль → Настройки → Экспорт JSON**. Сохраните личную копию в «Файлы» или другое безопасное место. **Не загружайте JSON на публичный GitHub.**
2. Распакуйте `KEREK_3_3_Update.zip`. В существующем репозитории `Marklanskoy/KEREK-PLUS-` выберите **Add file → Upload files** и загрузите содержимое архива в корень, заменив одноимённые файлы. Не загружайте сам ZIP и не создавайте внешнюю папку. `index.html`, `release.json`, `update.html`, `sw.js` и иконки должны лежать рядом.
3. Нажмите **Commit changes**, дождитесь успешной публикации GitHub Pages. Адрес, домен, ветку и папку публикации менять не нужно.
4. Закройте другие вкладки KEREK и установленную на домашнем экране старую версию. В том же браузере откройте после публикации:

   `https://marklanskoy.github.io/KEREK-PLUS-/update.html`

5. Нажмите **Сохранить копию перед обновлением**, сохраните файл, отметьте подтверждение и нажмите **Открыть KEREK 3.3.0**. Эта страница проверяет согласованность файлов, а не очищает пользовательскую базу.
6. Сверьте корзину, избранное, домашние запасы, реальные расходы и историю тестовых заказов. Сделайте новый полный экспорт. Сначала опробуйте изменения на тестовых данных.

**Не очищайте Safari/Chrome, localStorage или другие данные сайта. Не удаляйте прежний репозиторий.** Записи привязаны к браузеру и прежнему адресу. Другой браузер, приватная вкладка или новый домен не получают их автоматически.

Если страница пишет, что файлы ещё не согласованы, дождитесь окончания публикации и повторите. Не создавайте пустую базу поверх старой и не перезаписывайте свои записи демонстрационной копией.

## Что изменено

### 1. Восстановление удалённого товара

«Вернуть» восстанавливает только удалённые строки, не заменяя всю корзину старым снимком. Если после удаления молока вы увеличили количество хлеба, хлеб не откатится. Если ту же позицию уже добавили заново, её новое количество не перезаписывается.

При изменившихся остатках или недоступном товаре восстановление объясняет пропущенную позицию, а не молча урезает количество. Отмена полной очистки тоже не затирает товары, добавленные после неё. Повторная отмена не удваивает корзину.

### 2. Недоступные товары и новые остатки

Товар, исчезнувший из каталога, остаётся видимой строкой **«Товар больше недоступен»** с действием удаления. Строка объясняет, почему заказ пока нельзя оформить. Если доступно меньше, чем выбрано, можно уменьшать количество кнопкой **−** или нажать **Оставить доступное**. Увеличение ограничено остатком.

Общий итог при ошибках товаров обозначается как предварительный. Недоступные позиции не вычёркиваются без вашего решения. Реальность складского остатка этим не подтверждается: каталог демонстрационный.

### 3. Рецепт рассчитан — не значит заказ готов

Для рецептов, Autopilot и корзины используется общий расчёт готовности заказа. Отдельно проверяются доступность, количество, минимальная сумма товаров, промокод, зона и итог.

Например, молоко за 590 ₸ плюс доставка 990 ₸ дают 1 580 ₸, но при минимуме товаров 1 000 ₸ заказать нельзя: до минимума не хватает 410 ₸. Объяснение видно уже в подборке. Можно явно **перенести список для дополнения**, добавить только действительно нужное или отказаться от доставки. Это не автоматически готовый заказ.

Если всё есть дома, приложение показывает это и не пытается создавать пустой заказ. Доставка не считается частью минимальной стоимости товаров.

### 4. Промокоды

Статус кода обновляется вместе с корзиной. Если минимум перестал выполняться, код не подписывается «Применён»: видно условие и недостающую сумму. Недействительный код можно убрать отдельной кнопкой. Итог и скидка рассчитываются по текущим условиям.

### 5. Черновики оформления и отзывов

Адрес, комментарий, зона, интервал и политика замен сохраняются локально в черновике. Текст и тема неотправленного обращения тоже восстанавливаются после смены темы и нового открытия. Изменения записываются с небольшой задержкой и при уходе с экрана; при отказе записи выводится ошибка, ввод остаётся в текущей форме.

Черновик доступен для восстановления **в течение 7 дней после его изменения**. Проверка давности выполняется при загрузке: это не обещание фонового удаления ровно через семь суток. Редактирование отзыва не продлевает срок адресного черновика. Внешние экспорты и локальные резервные копии могут содержать прежние данные, их жизненным циклом нужно управлять отдельно.

**Очистить форму** убирает текущий черновик оформления, но не корзину и не адреса, отдельно сохранённые в профиле. Успешный тестовый заказ очищает черновик оформления и лимит этой покупки.

Согласие с тестовым заказом не переносится через закрытие/новый запуск и не импортируется. В текущем сеансе смена темы не сбрасывает его. При изменении суммы, состава, адреса, интервала или других значимых условий требуется новое согласие с видимым объяснением. Устаревший интервал не подменяется молча: выберите новый.

Черновики не зашифрованы. Не вводите настоящие платёжные данные в бете.

### 6. Назад и вперёд

Переходы внутри приложения создают историю. «Назад» возвращает с товара в корзину, сохраняя её позицию прокрутки; «Вперёд» восстанавливает следующий экран. История хранит только состояние экрана, не старые версии корзины: возврат не отменяет сделанные покупки/изменения.

Первое открытие по `#cart` также поддержано. Жест Safari на физическом iPhone требует отдельной проверки; тесты здесь подтверждают History API в Chromium на DOM-стенде.

### 7. Итог всегда рядом на телефоне

В заполненной корзине под экраном и над нижней навигацией закреплён **полный итог с доставкой** и кнопка **К оформлению**. При ошибках кнопка ведёт к объяснению, а не скрывает причину выключенного оформления.

Это переход к форме, не автоматическое создание заказа. Окончательное подтверждение — отдельной кнопкой. Поля и низ страницы имеют запас места, а панель скрывается при наборе в поле, чтобы не мешать. Реальная виртуальная клавиатура iOS/Android не проверена.

Кнопки количества увеличены. При нажатии Enter фокус сохраняется; если кнопка «+» стала недоступна из-за максимума, фокус переходит к доступному управлению, а не пропадает. Изменённое количество и итог сообщаются через ненавязчивый статус для вспомогательных технологий.

### 8. Лимит покупки в корзине

Рядом с итогом можно **задать или изменить лимит этой покупки**. Он сравнивается с полной стоимостью, включая доставку. Бюджет, выбранный в Autopilot или подборе рецептов, переносится вместе с применённым списком. При отсутствии пользовательского выбора произвольный лимит не подставляется.

Превышение видно и в итогах, и в мобильной панели. Оно не выдается за ошибку банка или списание из личного запаса: для тестового оформления выше лимита нужно отдельное подтверждение.

Это ориентир одного заказа, **не** остаток реальных денег и **не** повторное списание из семейного бюджета. После завершения или очистки корзины ориентир можно убрать/задать заново; при успешном заказе он сбрасывается.

### 9. Режим просмотра второй вкладки

Вторая вкладка по-прежнему не может перезаписывать данные первой. Кнопки изменения заранее отключены и рядом есть объяснение. Закройте первое редактирующее окно, затем нажмите **Разрешить редактирование** во втором. Внесённый во втором окне текст формы сохраняется в памяти до получения права записи.

При отсутствии Web Locks запись не включается обходным способом. В неподдерживаемом браузере будет просмотр. После любого обновления старые вкладки надо закрыть: старый клиент не понимает новых правил.

## Совместимость

Основная схема остаётся `version:32`; имя локальной базы остаётся `kerek_3_2:<путь приложения>`. Номер выпуска 3.3.0 не означает создание новой пустой базы. Добавлены необязательные `checkoutDraft`, `supportDraft`, `cartBudget`; счета магазина и личные записи Autopilot не стираются.

Старый импорт 3.2 принимается; незнакомые новые поля не требуются для открытия старой копии. Для 3.0 и более ранних версий сохранён прежний механизм миграции. Импорт **заменяет, а не объединяет** истории и требует подтверждения. Перед ним создаётся локальная копия. При удалении данных/выходе очищаются и черновики текущего клиента; файлы, скачанные отдельно, удаляются пользователем.

Полный экспорт содержит все новые поля, но не согласие на заказ. Не открывайте старый исполняемый клиент параллельно с новым: совместная запись разных версий не поддерживается.

## Что осталось прежним

Каталог, поиск, избранное, история просмотра, рецепты, домашние запасы, Autopilot с регулярными количествами, отдельный учёт реальных расходов, тестовые заказы и экспорт/импорт сохранены. Оранжево-жёлтая иконка K с корзиной остаётся подключённой к favicon, Apple Touch Icon и манифесту.

Тестовые заказы не уменьшают журнал реальных трат. Локальное обращение в поддержку остаётся черновиком с ручным копированием/отправкой: владелец не получает его автоматически. В отдельной серверной демонстрации доступна авторизованная поддержка через админ-панель.

## Разработчику

`public/` — редактируемые источники, `server/` — FastAPI/SQLite в демонстрационном режиме, `tools/` — шаблоны обновления, `tests/` — регрессионные проверки. `dist/` — готовые файлы GitHub Pages, `dist-server/` — сборка с явно включённым серверным режимом.

**Не редактируйте только `app.js` рядом с `index.html` на хостинге:** в этой версии исполняемый JS встроен в согласованную HTML-сборку. Измените исходник в `public/`, затем выполните сборку.

```bash
python build.py
python -m http.server 8000 --directory dist
```

Для сохранения используется HTTPS или localhost, браузер с Web Locks. Предпросмотр HTML в приложении «Файлы» на iPhone не является запуском сайта.

Проверки (Node.js 22 и Python):

```bash
node --test tests/core.test.cjs tests/reliability.test.cjs tests/cart.test.cjs tests/package.test.cjs
python -m pip install -r requirements-dev.txt
python -m pytest tests/test_api.py tests/test_release.py -q
python tests/ui_model.py
python tests/cart_ui_model.py
```

DOM-проверки требуют Python Playwright и Chromium. В данной среде Chromium установлен как `/usr/bin/chromium`. В скриптах явно подставлены модели хранения и блокировок. Они не заменяют тесты настоящей браузерной сессии.

Для серверной демонстрации:

```bash
python -m pip install -r requirements.txt
python build.py
python -m server.manage create-admin --username admin
python -m uvicorn server.app:app --host 127.0.0.1 --port 8000
```

Администратор задаёт свой пароль в терминале. Перед закрытым HTTPS-тестом настройте `KEREK_ORIGIN`, `KEREK_ALLOWED_HOSTS`, `KEREK_SECURE_COOKIES=1`; SQLite храните вне web-каталога. Docker требует предварительной сборки: `python build.py`, затем `docker compose up --build`. Docker здесь не собирался. Не включайте настоящий платёж, просто переименовав демонстрационный режим.

## Ограничения выпуска

- Исправления не превращают демокаталог в реальный магазин. Остатки, цены, оплата и доставка не подтверждены поставщиком.
- Банки, SMS, внешняя нейросеть и публичное размещение Python-сервера не подключены.
- Локальная база/копии не зашифрованы. PIN/пароль интерфейса не следует считать шифрованием данных. Защищайте устройство и скачанные файлы.
- Нет безопасного объединения изменений разных устройств; один клиент с правом записи, остальные просматривают.
- Сроки годности/составы берутся из внесённых данных. Не используйте демокаталог для решений об аллергии без проверки реальной упаковки.
- Казахские подписи не проходили полную редактуру носителем языка.
- Настоящие localStorage/Web Locks, офлайн-установка PWA, физические iPhone/Android, скринридеры и Docker не проверены. Native URL в рабочей среде заблокирован. Это бета, не полный аудит безопасности/производительности/доступности.

Точные результаты и область тестов — `TEST_REPORT.md`. Перед важными записями: внешняя копия → сверка после обновления → тестовая операция → закрыть/открыть приложение → проверить сохранение → новый экспорт.
