# KEREK 3.4.0 — Стабильность и понятные покупки

Подготовлено 13 октября 2026 года. Основа: KEREK 3.3.0, commit `161d5b6872ea8febed75f26f54ee6cacb1fcdab6` репозитория `Marklanskoy/KEREK-PLUS-`. Autopilot 2.2.0. Не новый проект с нуля: прежние функции и оранжево-жёлтая иконка сохранены.

**Это файлы обновления, не подтверждение публикации. Каталог, цены, склад и заказы остаются демонстрационными. Настоящей оплаты, доставки, SMS и внешней нейросети нет.** Подготовка ZIP не превращает GitHub Pages в действующий магазин. Выпуск не является обещанием отсутствия всех ошибок или необходимости дальнейшего сопровождения.

## Установить, сохранив данные

1. В прежнем KEREK откройте **Профиль → Настройки → Экспорт JSON**. Сохраните личную копию отдельно. Никогда не загружайте её в публичный репозиторий.
2. Распакуйте `KEREK_3_4_Update.zip`. Через **Add file → Upload files** загрузите **содержимое архива в корень прежнего репозитория** `Marklanskoy/KEREK-PLUS-`, заменив одноимённые файлы. Не загружайте сам ZIP и не создавайте дополнительную папку.
3. Нажмите **Commit changes**, дождитесь успешной публикации GitHub Pages. Сохраняйте прежний адрес, браузер, домен и папку публикации. Для этого обновления не нужны новые настройки сервера или аккаунта.
4. Закройте другие вкладки KEREK и прежнюю копию с домашнего экрана. В том же браузере после публикации откройте:

   `https://marklanskoy.github.io/KEREK-PLUS-/update.html`

5. Нажмите **Сохранить копию перед обновлением**, сохраните JSON, отметьте подтверждение и нажмите **Открыть KEREK 3.4.0**. Страница проверяет выпуск, затем согласованность установленного Service Worker. При ошибке не очищайте браузер: перечитайте сообщение и повторите после завершения публикации.
6. Проверьте корзину, избранное, адреса, расходы и историю тестовых заказов. Создайте новый полный экспорт. При первом переходе с базы 3.2/3.3 записывается дополнительный локальный оригинал `before-3.4`. Он доступен внутри **Копии для восстановления**, но не заменяет внешний JSON.

**Не очищайте Safari/Chrome, localStorage или данные сайта. Не создавайте пустую базу вместо прежней.** Записи другого браузера/домена/приватного режима не появляются автоматически. Смена файлов не должна требовать ручного повторного ввода расходов.

Обновление сохраняет схему `version:32` и ключ `kerek_3_2:<путь приложения>`. Название ключа — внутренний идентификатор совместимости, а не номер текущего интерфейса. Страница обновления собирает и старые отдельные ключи Autopilot.

В архив включены неисполняемые страницы для старых адресов `KEREK_2_0.html` и `KEREK_3_0.html`. Они направляют на актуальный клиент, ничего не записывая. Уже открытые старые вкладки всё равно нужно закрыть: замена файла на сервере не останавливает ранее загруженный JavaScript.

## Первые две минуты

### Хочу просто купить продукты

**Каталог → добавить товары → Корзина**. В итогах указана полная стоимость с тестовой доставкой, промокодом и бонусами. Недоступные товары и превышения показываются явно. На телефоне итог и кнопка «К оформлению» остаются над нижней навигацией. Создаваемый заказ — только демонстрационный, курьер не выезжает.

### Хочу повторять обычные покупки

На главной: **Открыть список → Выбрать товары**. Укажите подтверждённые количества на неделю, например четыре упаковки молока, и бюджет всей покупки. **Посмотреть подборку** не изменяет корзину. После просмотра подтвердите **Применить к корзине**. Избранное и история — подсказки, не автоматическое назначение регулярных покупок.

### Не понимаю функцию

На любом обычном экране есть короткая строка **Как пользоваться**. В справке три входа: каталог, регулярные покупки, данные и копии. Раскрываемые ответы объясняют, чем отличаются план и расход, где находятся копии, что означает режим просмотра и как рассчитывается итог. Не нужно проходить обязательную длинную анкету.

## Что улучшено в 3.4

### Проверка данных до изменения базы

Вложенные строки заказов, количества корзины, денежные поля, даты домашних запасов, повторные идентификаторы и лимиты размера проверяются до импорта/сохранения. Повреждённая история не отбрасывается молча, чтобы «импорт прошёл». Приложение останавливается с объяснением и позволяет сохранить исходные записи. Если повреждена копия, исправлять цифры наугад нельзя.

Перед восстановлением показываются количества заказов, избранного и реальных расходов. Импорт **заменяет, не объединяет** базу; требуется подтверждение. Сохраняется локальная копия состояния перед заменой. Незавершённый запрос заказа из импортированного файла не воспроизводится автоматически. Идентификаторы избранных товаров, которых временно нет в каталоге, сохраняются в базе и экспорте.

Строгая проверка может остановить восстановление старой вручную изменённой копии, которую прежний клиент частично принимал. Это намеренная защита от скрытой потери записей, а не автоматический ремонт файла.

### Защита расчёта стоимости

Отрицательные/нечисловые цены, повреждённые остатки и настройки, переполнение суммы или невозможные бонусы не разрешают оформить заказ. Такие значения не превращаются в `NaN`, бесплатную покупку или фиктивную скидку. Отсутствующая старая цена не создаёт «экономию».

Срок промокода считается по дате Алматы и одинаково определяется в JS и серверном расчёте. Бюджет Autopilot с неверным числом не разрешает применить подборку. Будущий запланированный расход нельзя записывать как уже оплаченный расход в личном журнале.

### Защита от повторной отправки

Во время запроса создания заказа недоступны изменения корзины и повторный submit, включая submit после перерисовки. Запрос имеет сохранённый idempotency key; повторная попытка не создаёт новый ключ без изменения содержимого.

Если сервер уже подтвердил заказ, а затем обновление каталога не получилось, интерфейс сообщает **Заказ сохранён**, а не «заказ не отправлен». Если подтвердил сервер, но не получилось записать ответ локально, появляется явное предупреждение с идентификатором и предложением проверить серверную историю. Не оформляйте заново до сверки. Подтверждение здесь относится к тестовому серверу, не к реальному магазину.

Фоновая загрузка профиля не применяется поверх более новой локальной ревизии. Обновления профиля отправляются последовательно. Это защита выбранных сценариев, не полноценная синхронизация нескольких устройств; регулярный список и личные расходы Autopilot по-прежнему локальны.

### Надёжнее обновление и восстановление

Service Worker до установки проверяет SHA-256 полного комплекта критичных файлов: HTML, manifest и иконки. Смешанный/неполный комплект отклоняется до записи новой пачки в кэш; старый активный выпуск не удаляется принудительно. Страница обновления ждёт именно нужные номер версии и build id, а не любую активную старую копию.

Контрольная сумма проверяет согласованность файлов, **не доказывает их доверенное происхождение** при компрометации сервера. Проверки выполнены на модели Service Worker; реальную установку на iPhone нужно проверить отдельно. При отсутствии сети онлайн-обновление не обещается.

Ошибки записи не оставляют на экране ложное изменённое количество. Первоначальный код и копии не удаляются при ошибке импорта. Локальные копии исчезают вместе с удалёнными данными браузера — внешний JSON обязателен.

### Понятнее интерфейс

- Справка доступна с обычных экранов; главная навигация не расширена новым обязательным разделом.
- «Меню под бюджет» не называется подключённой нейросетью: это локальный алгоритм.
- При отсутствии сети отображается статус. Он основан на состоянии браузера, не на проверке доступности магазина.
- Диагностика показывает версию, режим и доступность браузерных возможностей. Экспорт диагностической информации не содержит адресов, телефонов, корзины, комментариев и сумм. Он не является сертификатом надёжности или проверкой реальной доставки.
- Отложенный поиск не перебрасывает пользователя из уже открытой корзины в каталог.
- Учитывается системное предпочтение уменьшенного движения.

## Что сохранено из 3.3

Точная отмена удаления; видимость недоступных SKU; уменьшение количества выше складского остатка; проверка минимального заказа в рецептах/Autopilot/корзине; актуальность промокода; черновики; Back/Forward и прокрутка; мобильный итог; лимит покупки; сохранение фокуса; режим одного редактирующего окна. Экспорт/импорт, расходы, домашние запасы, рецепты, клуб и история остаются доступны.

## Хранение и ограничения

- Каталог/заказы демонстрационные. Оплата, исполнение заказа, реальные цены/остатки, SMS и внешняя нейросеть не подключены.
- Только один редактирующий клиент на этом браузере/origin через Web Locks. При отсутствии поддержки запись отключена; другие вкладки только просматривают. Это не многопользовательская облачная синхронизация.
- Локальная база и JSON не зашифрованы. Они доступны программам этого origin и человеку с доступом к устройству. Диагностическая копия отделена от личной финансовой/покупательской базы.
- Выход удаляет локальные записи после подтверждения. Перед выходом экспортируйте данные. Личные расходы и регулярный список сервером не синхронизируются. Удаление охватывает собственные прежние ключи и локальные снимки; внешние скачанные JSON нужно удалять отдельно.
- Черновики доступны до семи дней после редактирования; срок проверяется при запуске, не означает физическое удаление всех копий в точный момент. Согласие на оформление после нового запуска не восстанавливается.
- Подтверждение запасов не старше 14 дней — правило актуальности записи, не срок безопасности продуктов. Рецепты/замены нельзя использовать как медицинскую проверку аллергии.
- Поддержка в статическом режиме — локальный черновик, который пользователь сам копирует/отправляет выбранному получателю. Системное «Поделиться» не подтверждает получение владельцем. Авторизованные обращения серверного демо доступны в админ-панели после отдельного запуска сервера.
- Нет доказательства безошибочности: не выполнены полноценный аудит безопасности, нагрузочный тест, VoiceOver, физический iPhone/Android и native PWA/offline. Политика среды заблокировала настоящее открытие URL. См. TEST_REPORT.md.
- Казахские подписи проверены технически, но не прошли отдельную редактуру носителем.

## Для разработчика

`public/` — исходники; `safety.js` — новая проверка состояния; `build.py` — детерминированная сборка; `tools/` — шаблоны обновления/Service Worker; `server/` — FastAPI/SQLite; `tests/` — регрессии и модели UI; `dist/` — готовые файлы GitHub Pages; `dist-server/` — отдельная серверная сборка.

Для изменения приложения редактируйте `public/`, затем запускайте сборку. Исполняемый код встроен в `index.html`: изменение только внешнего `app.js` рядом с готовым index не обновит интерфейс. Базы, пароли и пользовательские JSON в GitHub не публикуйте.

```bash
python -m pip install -r requirements-dev.txt
python tools/check_release.py
# Дополнительно: Playwright + Chromium /usr/bin/chromium
python tools/check_release.py --ui
```

Скрипт пересобирает приложение, запускает JavaScript/серверные тесты и проверяет контрольные суммы. `--ui` добавляет явно модельные тесты интерфейса. Это не автоматическая публикация и не тест настоящего телефона. Публичный репозиторий с готовыми файлами не содержит полного каталога исходников — команду запускают из распакованного **Source.zip**.

Локальный статический стенд: `python -m http.server 8000 --directory dist`. На iPhone используйте опубликованный HTTPS-адрес, а не предпросмотр index.html в «Файлах».

Серверная бета:

```bash
python build.py
python -m server.manage create-admin --username admin
python -m uvicorn server.app:app --host 127.0.0.1 --port 8000
```

Пароль администратора задаётся в терминале (минимум 14 символов). `.env.example` — справка, автоматически не загружается. Для закрытого HTTPS-стенда настраиваются `KEREK_ORIGIN`, `KEREK_ALLOWED_HOSTS`, `KEREK_SECURE_COOKIES=1`. SQLite вне web-каталога. Docker — `python build.py`, затем `docker compose up --build`; сборка Docker в этой среде не выполнялась. Сервер намеренно демонстрационный, эту защиту не отключайте ради реальных оплат.
